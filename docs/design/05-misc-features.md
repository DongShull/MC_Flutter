## 1. 离线下载（core/offline + features/offline）

### 1.1 总原则

1. **本机副本自包含**：视频、字幕、字体、展示数据、图片放同一目录树；目录即事实来源，删目录即删干净。
2. **页面不知道离线**：媒体库的四处读请求收口到取数层 \`LibraryReads\`；在线走接口并回写本机，离线或失败读本机。
3. **离线只是界面模式，不影响播放**：本机副本在线时也优先播；网络判断只决定媒体库显示什么。
4. **先落盘再发送**：下载状态、观看记录都「先写文件、服务端按编号幂等合并」。
5. **期望状态 + 对账**：要下什么记在本机；后台任务实际有哪些由对账补齐，崩溃、被杀、断网后自愈。

### 1.2 网络判断（core/offline/reachability.dart）

两层分开：

- **可达性**（事实估计，三档：可达 / 存疑 / 不可达）——只回答「现在能不能和服务器说上话」。
- **模式**（界面，在线 / 离线）——由可达性加切换规则决定。播放不看模式。

**证据旁听**：所有页面请求经 \`core/api\` 的 GeneralChannel 出口；在把错误映射成 \`ApiException\` 之前，
把原始 \`DioException\` 交给 \`ReachabilityJudge\`，不发额外请求。以下不计入：非当前服务器的请求、
主动取消（CancelToken 已触发）、SSE/图片/视频字节流、回前台之前发出之后才失败的（App 挂起被系统掐断，
回前台报 -1005 类错误不说明网络坏了）。

**探测**：\`GET /api/v1/health\`，5 秒超时。只在两种时候发：存疑或不可达时；冷启动、或后台超过 10 分钟
回前台后 3 秒内页面请求一个都没成功时探一次。探测也走同一出口，判定只有一条证据通道。

**网络通路**：复用 \`connectivity_plus\` 的 Connectivity 流（对应原 \`NWPathMonitor\`），发布
\`none / wifi / mobile / ethernet\`；不另起监视器。播放的计费网络判断（低数据模式 / 个人热点语义）
沿用同一来源。

**服务器身份**：所有 \`/api/v1\` 响应带 \`X-Movieclaw-Spec-Hash\` 头（服务端中间件加）。收到不带此头的响应
（机场门户页、反代 502、外地局域网同 IP 设备）一律硬失败。\`health.instance_id\` 用于账号键与身份核对。

**归类**：

| 结果 | 归类 |
|---|---|
| 收到带标记头的响应（任何状态码，含 401/500） | 成功 |
| 通路 \`none\`（飞行模式、无 Wi-Fi 无蜂窝） | 断网，确定 |
| 连接被拒 / 主机不可达；TLS 或证书错误；无标记头响应；蜂窝被禁、漫游关闭 | 硬失败 |
| 超时、连接中断、DNS 失败、其他 | 软失败（信号差时 DNS 也会超时，所以算软） |

**判定规则**（纯逻辑类 \`ReachabilityJudge\`，单元测试按时刻喂事件序列）：

- 任一成功 → 可达，清零全部计数；
- 通路 \`none\` → 立即不可达；
- 可达时一次失败 → 存疑并开始探测：立即一次，之后每轮间隔 2 秒；
- 存疑转不可达（满足任一）：连续硬失败 ≥2 且从第一次起 ≥3 秒，中间无成功（夹一次软失败重新数）；
  或连续失败 ≥3 次（软也算）且从第一个失败请求发出起 ≥30 秒——服务器 30 秒没回过任何话；
- 不可达时继续探测：通路变化、回前台、用户点「重新连接」立即探；前台按 30s→60s→2min→5min 退避封顶；后台不探。

**模式切换（进难出易）**：

- 自动进离线仅两种情况：①通路 \`none\`（飞行模式，意图明确）；②不可达发生在冷启动后 60 秒内、或长后台
  （>10 分钟）回前台后 60 秒内——此时用户还没在看服务器内容。
- 使用途中断网不自动切：在媒体库首页既有「与后端通信失败」提示条上加按钮「看本机的 N 部」，点了才切。
- 恢复连接后自动回在线并轻提示「已连上服务器」；已推入的详情页不动（有副本的条目两种模式都能显示）。
- 本机一部都没下过时永不进离线模式，维持「首页快照 + 提示条」现状。

网慢不会误切的理由：慢请求只要回来就是成功立即清零；单次超时只进「存疑」界面不变；只有超时类失败要连续
三次且 30 秒无任何响应才判不可达（探测 5 秒传回几百字节，30 秒一次都做不到就不是慢而是断）；就算判了
不可达，途中也只给按钮；切错代价小，任一成功立即切回，播放完全不受影响。

### 1.3 本机存储（core/offline/offline_store.dart）

**选型**：每条目一个目录 + JSON，不用 SQLite/Hive/Isar。理由：条目几十到几百个，唯一查询是「列出本账号
全部」；展示数据就是接口模型原样存档，零映射代码；目录即事实来源，不存在索引与文件不一致。与首页快照
同一套路。

**目录**（账号键 = sha(实例号 | 用户名)，不用服务器地址——局域网 IP 与域名切换不丢副本）：

\`\`\`
<Application Documents>/Offline/<账号键>/
  owner.json                    服务器地址、实例号、用户名（存储页「其他账号」用）
  items/<media_item_id>/
    summary.json                索引用小文件：类型、片名、年份、海报键、所属库、各单元摘要、总大小、最近下载时间
    detail.json                 详情接口模型原样
    library.json                媒体库视图原样
    seasons/<季号>.json          分集视图原样，只存有下载的季
    progress.json               本机续播点：每单元 {position_ms, played, updated_at}
    images/<键>.<扩展名>         图片键 = 地址去掉服务器前缀与宽度参数后的部分，保留 v；TMDB 绝对地址再去尺寸段
    units/<file_id>/
      unit.json                 单元状态机（§1.7）
      media.<扩展名>
      subs/  fonts/
      playback.json             时长、片头片尾段、章节、音轨与字幕清单、下载时默认轨
  viewings/<viewing_id>.json    待同步观看记录（删除条目不删它们）
\`\`\`

单元以服务器 \`file_id\` 为键：一集多版本只下其一，洗版换文件后旧副本照样能播。

**写入与读取**：

- **单写者**：所有改动（下载回调、删除、元数据刷新、进度写入）经同一个串行执行器——Dart 侧用一个
  持有全部状态的 \`Notifier\` + \`synchronized\` 串行队列（或常驻 Isolate），无并发写竞争。界面读它发布的只读快照。
- **一律原子写**：先写 \`.tmp\` 再 rename。
- **视频落盘顺序**：下载回调里先把文件 move 进单元目录（同卷 rename O(1)），再原子写 \`unit.json\` 标完成；
  两步之间崩溃由启动对账补标（文件在、大小对、状态没标 → 补标）。
- **启动建索引**：后台 Isolate 扫 \`items/*/summary.json\` 建内存索引（每条约 1 KB，500 部 < 10 ms）；
  \`detail.json\` 打开详情页才读（解码 < 5 ms）。
- **文件保护**（iOS）：默认等级（首次解锁后可读写），锁屏后台下载也能写；整个 \`Offline/\` 排除 iCloud 备份。
- **格式版本**：自有结构（summary/unit/playback/progress/viewing）带 \`format\`；不认识的版本跳过该条目不崩溃。
- **模型存档兼容**：模型新增字段会让旧 \`detail.json\` 解码失败。对策：①升级后首次在线时后台按序重拉全部
  副本展示数据；②离线解码失败退回仅靠 \`summary.json\` 的极简详情（海报、片名、各单元播放与删除）。

### 1.4 取数层（core/offline/library_reads.dart）

四处读请求收口：\`libraryItemsGet\`、\`libraryGet\`、\`libraryItemsListEpisodes\`、\`playbackResume\`。

| 情况 | 行为 |
|---|---|
| 离线模式 | 只读本机；无副本条目返回「离线不可用」 |
| 在线，有副本 | 本机数据秒开，静默拉服务器并回写本机；拉取失败停在本机，每 10 秒重试，成功回到在线详情 |
| 在线，有副本，服务器 404 | 显示本机版本，注明「服务器上已删除」，仍可播、可删 |
| 在线，无副本 | 照旧走接口 |

读本机数据统一变换（在线失败回落时同样做）：\`files\` 只留本机有的；\`seasons\` 只留有下载的季；
\`owned\` 改为「本机有没有」（没下载的集自然沿用缺集置灰）；\`positionMs/played\` 取本机进度与存档中较新一份。

离线首页与离线海报墙是新写薄视图：复用海报墙 / 海报卡组件；首页海报行、「接着看」卡片组件保持可复用；
不复用在线首页 Store（偏好、指纹、轮询都是为服务器准备的）。

**图片**：图片加载器（带鉴权头）先按图片键查本机：离线直接用本机文件不发请求；在线仅请求失败回落本机。

### 1.5 用户可见行为

| 场景 | 在线 | 离线 |
|---|---|---|
| 媒体库首页 | 照常；有排队或下载中的单元时顶部一条「正在下载」提示条 | 两部分：「接着看」（本机有续播点的）+ 按库分组的已下载条目；不还原自定义首页 |
| 海报墙 | 照常 | 该库已下载条目，按最近下载或片名排序，无筛选 |
| 详情页 | 照常；播放键旁显示下载状态，分集卡标「已下载」 | 只读：隐藏管理菜单、收藏、标记已看、相似推荐、系列；分集列表照常，没下载的置灰 |
| 播放 | 有本机副本优先播本机，否则走服务器 | 只能播本机副本 |
| 底部「接着看」条 | 照常 | 不显示（来自服务器可能指向没下载的片） |
| 订阅、发现、活动、搜索、AI | 照常 | 占位：「离线中，需要连接服务器」 |
| 我的 | 照常，多一个「下载」入口 | 账号卡 +「下载」，其余隐藏 |

- 海报卡不加「已下载」角标（沿用定稿）。
- 首页「正在下载」是汇总提示条（\`OfflineDownloadingRow\`）：「N 部正在下载 · 总速度 · 还剩几个 · 总进度」，
  左侧总进度环；全部暂停写「已暂停下载」，只剩中断的变警告色；点进「我的 → 下载」。首页不放每集剧照卡，
  下载细节收进存储页。
- 在线时已下载的片子在详情页标出（播放键旁状态条 + 分集卡），优先播本机。

### 1.6 服务端接口与档位

新增 \`offline\` 路由（成员区，Bearer 设备令牌鉴权，校验 \`allow_video_download\` 与库访问权限）：

| 接口 | 作用 |
|---|---|
| \`GET /offline/manifest?file_id=\` | 一次给齐打包所需一切：item、library、season、单元信息、playback（时长/片段/章节/轨道清单/默认轨）、字幕字体图片地址、可用档位与预计大小 |
| \`POST /offline/profiles\` | 选档面板：一批文件（≤500）各自可选档位与预计大小、季集与容器；面板打开时一次问完，切范围不再请求；旧服务器 404 时退回逐集取清单 |
| \`GET /offline/files/{file_id}/content\` | 原画字节；Range / ETag / If-Range 现成；登记到活动页「正在下载」 |
| \`POST /offline/exports\` | \`{file_id, profile, audio_track?}\` → \`export_id\`、状态、ETag、预计大小 |
| \`GET /offline/exports/{id}/content\` | 导出文件（边转边下） |
| \`DELETE /offline/exports/{id}\` | 下完通知回收（尽力而为，服务端另有 72 小时过期） |
| \`POST /playback/viewings\` | 观看记录批量补传 |

**档位**：原画（原文件字节）/ 1080p（HEVC 4 Mbps，NAS 无硬 HEVC 时 H.264 6 Mbps）/ 720p（2 / 3 Mbps）/
480p（1 / 1.5 Mbps）。服务端在清单里给出每个文件**可用**的档位和预计大小，客户端照单列出——以后加档位
不用发 App。预计大小 = 码率上限 × 实测系数（VideoToolbox HEVC 0.55 / VT H.264 0.57 / 软件 0.83）+ 音轨，
乘片长，界面写「≈」；原画写文件实际大小。

**轨道**：转码档只带一条音轨（默认取服务端按偏好选的那条，下载 sheet 可改）；文本字幕全部单独下载
（ASS 连同字体）；图形字幕（PGS）一期转码档不带。

**没有可选档位时**：HDR 片在无硬件转码的服务器上无转码档；原盘（BDMV/ISO）一期不能下载，按钮置灰写原因。
strm 原画一期一律服务端中继（不 302 到云盘直链，避免后台下载把设备令牌带给网盘）。

**导出内容接口按状态响应**：

| 状态 | 响应 |
|---|---|
| 已完成 | 静态文件：Content-Length + ETag，支持 Range / If-Range 续传 |
| 进行中 | 200 分块传输，从头开始、跟着文件增长发；只有正常结束才算完成，失败掐断连接（客户端必报错，不会把半个文件当完成） |
| 排队中 | 503 + Retry-After + \`x-export-wait\`（\`queue\` / \`transcoder\`）+ \`x-export-ahead\`（前面还有几个） |
| 失败 | 422 + 原因码 |

界面据 503 写「等待转码，前面还有 N 个」「即将开始转码」「等待转码器空闲」，正常颜色 + 沙漏图标，
**不写「下载中断」**。ETag = 导出号 + 代号：缓存被清、服务重启重跑都换代号，续传 If-Range 不匹配时服务端
回整份 200，客户端从头下，不会拼出坏文件。

**下载 sheet**：列出可用档位、各档预计大小、本机剩余空间；记住上次选择作默认。

### 1.7 客户端下载器与对账（core/offline/downloader.dart）

**单元状态机**：

\`\`\`
准备中（拉清单、字幕、字体、图片）→ 排队 → 下载中 → 完成
     ↘ 失败（可重试 / 不可重试）   暂停 ↔ 下载中
\`\`\`

**下载执行**：

- **iOS**：后台 \`URLSession\` 会话两条——仅 Wi-Fi 与蜂窝均可；带 \`Authorization: Bearer <设备令牌>\`
  （设备令牌不过期，不用 12 小时播放签名；切账号后其他账号下载照常）；任务的描述字段写单元身份
  （账号键、条目、file_id、代号），重启后据此对回单元。经 platform channel 宿主实现，或一期用
  \`flutter_downloader\` 包装后台任务。
- **Android**：WorkManager 长时作业（前台通知，类型 dataSync）代替系统后台会话；「只用 Wi-Fi」= 不计费网络
  约束；续传靠 \`media.part\` + Range + If-Range（ETag 记在 \`unit.json\`）。转码档下完后做 fMP4 修整
  （负 tfdt 改 0、补 sidx，对应原 \`Fmp4Fixup\`）供 ExoPlayer 兼容——本项目 media_kit（FFmpeg）两者都照读，
  修整仅在用 video_player 快路径时需要。
- **串行**：一次只下一个，排队的顺序就是优先级——排第一、能下的独占带宽，其余一个字节也不收（不是限速）。

**下载顺序与优先下载**：

- 默认顺序 = 加入下载先后；一次下一整季按集数。单元存档多一个可空 \`queueOrder\`：没调过为空按加入时间
  （Unix 秒）排；优先或拖动后，进行中的单元整体重编号 0、1、2…，之后新加的自然排后面。
- **优先下载** = 排到最前并立刻开始：正在下的让路（已下部分留续传），排它后面；暂停的、出错的优先 =
  继续 + 排最前；可连续用。排第一的还在等转码、还在准备时，不打断正在下的。
- 入口：详情页下载状态条菜单（「暂停」上方）、分集卡长按；剧集「⋯」里「优先下载剩下的 N 集」（仅当别的
  条目排在它前面时出现）；「下载」页按住拖动换先后（拖到最前、能马上下的立刻开始），长按菜单「优先下载」
  在第一项，轻扫同样操作。
- 显示：排队写「下一个下载」/「等待下载，前面还有 N 个」（N 只数会轮到的，暂停与待处理的失败不算）。
- **等 Wi-Fi 要说出来**：未开「使用蜂窝网络下载」时在蜂窝 / 个人热点 / 低数据模式下一动不动，排队和下着的
  都写「等待 Wi-Fi」，首页提示条同写；「下载中」顶上一条说明原因，带一键打开蜂窝下载的按钮。
- 串行保证：任务一律按下载顺序提交；优先 / 拖动后若排第一的换了人，连正在下的一起取消带续传重交；
  对账（前台）发现后到的单元要交任务而排它后面的已交未开始，取消后面那些、下一轮按顺序重交；任何任务
  开始收数据时对一次账——排前面的还在（在下或排着）而后面的却在收数据（切网络空窗场景），取消后面重交。
  只在前台做重排（后台新任务会被系统推迟）。

**重试**：网络类错误、5xx、503 按退避重试 30s→2min→10min→30min→之后每小时（503 可用定时延后触发，
不需要 App 醒着）。403（无权限）、404（文件没了）、422（不能转码）、空间不足不自动重试，写明原因，
可手动重试。

**空间检查**：开始前查剩余空间，要求 ≥ 预计大小 + 2 GB；不够提示、不入队。

**完成判定**：状态码 200/206；有 Content-Length 核对字节数；分块传输靠正常结束判断。都过了才 move 文件、
标完成。字幕、字体、图片、展示数据在「准备中」阶段并行拉取；视频和必需文件都齐才算完成，图片缺了不影响
完成（显示占位）。

**对账**（幂等）时机：启动、回前台、可达性恢复、后台会话事件唤醒、任务结束、删除、修改设置。每次对账：
应该有任务而任务列表里没有 → 有续传数据用续传数据重建，否则新建；有任务而单元已删 → 取消。用户强退后
系统取消全部任务（带续传数据），下次启动对账重建。自己取消的任务，续传数据由取消一方存好，代理不再写一次
（防止新任务读走删掉后又写回一份旧）。

### 1.8 播放本机副本

- 分流点在播放控制器向服务端发起协商之前：这一集（或电影）有已完成的本机单元 → 走本地源；否则照旧。
- 本地源：media_kit 以 \`file://\` 打开；不设字节缓存键；外挂字幕传本机文件；片头片尾段、章节、默认音轨
  字幕取自 \`playback.json\`，之后轨道选择沿用本机轨道记忆；不建服务端会话、不 ping。
- 起播位置：详情页传入的续播点（在线来自服务器、离线来自本机）；未传入时取本机进度与存档较新一份。
  在线起播本机副本时先问服务器续播点（最多 2 秒），本机有没发出去的记录时仍用本机的。
- 自动下一集：下一集有副本 → 播本机；在线无副本 → 照常走服务器；离线无副本 → 停在片尾。
- 引擎打不开本机文件 → 单元标「已损坏」，提示重新下载。预览缩略图（trickplay）一期不打包。
- （Android 语义）本机副本播放掉帧（解码跟不上）不算损坏：在线改走服务器，离线接着放。

### 1.9 进度与观看记录（viewings）

- **本机播放一律走观看记录，在线离线同一条路；流式播放保持现状**。两条通道不混用，一次观看不记两遍。
- 每次播放一个单元生成 \`viewing_id\`（UUID）。字段：\`media_item_id, season, episode, file_id, started_at,
  updated_at, position_ms, watched_ms, completed, duration_ms\`；\`watched_ms\` 只累计实际播放的墙钟时间。
- 每 10 秒及暂停、停止、退后台时原子写 \`viewings/<id>.json\`，同时更新该条目 \`progress.json\`。
- 本机续播点与服务端**同一套阈值**：不足 5% 不记、超过 90% 算看完、短于 5 分钟的片过了开头就算看完。
- 可达时立即发送最新快照，同一时刻只有一个在途请求；离线先留着，可达后批量补传（一批 ≤100 条）。
  一条记录同时满足「服务端已确认」和「本次播放已结束」才删除。与播放上报队列同一做法：先落盘再发，
  发成功才删，服务端按编号合并。
- 观看记录带启动编号：补传时上次启动留下、没结束的先收尾（防强退后永远「没结束」）。
- 服务端 \`POST /playback/viewings\` 逐条按 \`viewing_id\` 幂等 upsert：校时（偏差 = 服务器时间 − \`sent_at\`，
  超 7 天视为手机时钟不可信，一律按服务器时间）；按 \`file_id\` 定位条目与集，找不到再按 \`media_item_id\`，
  都找不到 \`rejected\`；续播状态只有 \`updated_at\` 更新才写（按发生时间不按到达先后）；观看日志首次插入
  play_count +1，\`watched_ms\` 取较大值且 ≤ ended − started + 2s；「已看」翻转发 \`playback.completed\`，
  \`started/progress/stopped\` 只在记录新鲜（2 分钟内）时发——补传旧记录不发，免得落地收到一串「开始观看」
  推送；返回 \`applied / stale / rejected\`，三种情况客户端都可删除。

### 1.10 删除与入口

| 位置 | 操作 |
|---|---|
| 电影详情页「⋯」 | 开始下载直接选画质；没下完时播放键上方玻璃胶囊状态条：进度环 +「下载中 47%」+ 实时速度，点它暂停/继续/重试/取消；下完收起；下载中「⋯」里「下载」换「取消下载」 |
| 详情页「文件」区 | 下完副本多一行（排最前，标「本机」），垃圾桶立即删除（不进回收站，确认说明删后没网不能播）；长按可改下其他画质 |
| 分集卡 | 没下完：剧照叠下载状态（蓝描边、「下载中 N%」+ 速度 + 进度条）；下完：右上角绿箭头「已下载」，短暂提示「下载完成」 |
| 剧集「⋯」 | 「下载」打开选档面板：「下载范围」规则——没下过的集给「第 N 集」，已下/在下换「接下来 5 集」；「未看 N 集」比剩余少时才有且默认；「全部 N 集」/「剩余 N 集」；重复范围只留一个，只剩一个不显示分段；说明本机已有的（「第 3 集已下载 · 已下载 3 集，不会重复下载」）；切范围时各档整批大小跟着变，选一次画质整批开始；有未下完的集时菜单临时多「取消下载选中的集」/「取消全部下载（N 集）」。菜单只读「各条目未下完的单元」派生值（仅在开始/完成/删除时变），进度刷新不重建开着的菜单 |
| 分集卡长按 | 「下载这一集 / 暂停 / 继续 / 取消下载 / 删除下载」；进度看卡上的下载条 |
| 海报卡长按 | 已下载条目菜单多一项「删除下载」（在线离线都有）；只进菜单不加可见控件 |
| 我的 → 下载 | 入口与页面都叫「下载」（不叫「缓存」）；先管下载、容量条放页面底部；「下载中」只在有未下完单元时出现，每集一行，下完移「已下载」；「建议」只在有看完的下载时出现（「删除已看完的」）；「已下载」按条目列出，点进媒体库条目，左滑或长按删除；「其他账号」分组也能删；下载设置在右上角齿轮（只有「使用蜂窝网络下载」，菜单内勾选） |
| 退出登录 | 询问「同时删除本机下载的 N 部（X GB）？」 |

删除规则：都要二次确认，写明能释放多少空间，说明「观看进度会保留」（待同步记录不随删除走）；离线同样可删
（只动本机）；删下载中的单元先取消任务再删目录；条目单元全删完，整个条目目录一起删。

### 1.11 账号与权限

- 服务器实例号：\`/api/v1/health\` 的 \`instance_id\`（新字段可空，旧服务器没有时视为不支持离线下载，
  下载按钮不出现）。用途：账号键组成 + 探测身份核对。
- 下载权限按成员权限的 \`allow_video_download\`：默认开、儿童预设关；关闭时下载接口 403。会话能力快照
  加可空字段，缺失 = 不支持。权限后来被关：不能再下新的，已下照常能播。
- **不做 DRM、不做远程擦除**；本机副本就是普通文件，安全边界在服务器。
- **令牌被吊销不自动删除下载**：副本跟着「实例号 + 用户名」走，同一账号重新登录就回来；也可在存储页
  「其他账号」手动删。
- 离线时不能切换账号（切换需连服务器验证）。

### 1.12 性能预算

| 项 | 预算 |
|---|---|
| 网络健康时 | 不发额外请求（只旁听），只用已有的一个通路监视器 |
| 启动 | 后台扫 N 个 summary.json，500 部以内 < 10 ms |
| 打开已下载详情 | 解码本机 detail.json < 5 ms，首帧即完整页面 |
| 下载进度 | 回调节流每秒一次，写进单元自己的可观察对象；海报墙只观察「已下载集合」（完成/删除才变），下载中不重绘 |
| 本机播放 | 直接读文件，不经字节缓存 |
| 观看记录 | 播放中每 10 秒一次小文件原子写 |

### 1.13 客户端版本来源（download-manifest 语义）

客户端包（Android APK / 侧载 IPA / 桌面版）版本来源是 GitHub Release 附件 \`downloads.json\`，与服务器更新
的 \`manifest.json\` 分开；各端独立发版（\`android-v\` / \`ios-v\` / \`macos-v\` …），沿用旧包不得改成服务器 tag
版本。App 内「检查更新」按本端产品名查各自 Release（见 §5），不从服务器 Release 取客户端包。

### 1.14 分期

- **D1 基础**：原画下载、本机播放、观看记录、删除、取数层（含秒开与回落）、下载页。做完飞行模式已可用。
  端到端验收：下载途中杀服务器再拉起续传完成（md5 一致）；停服播本机、拖动、看一半退出，恢复后补传，
  网页端续播点正确、观看统计开始时间是真实时间；各入口删除后空间释放、目录清空、进度保留。
- **D2 码率档**：导出 + 边转边下。验收：整季下载后台锁屏推进到完成；导出途中重启服务端换代号从头重下
  且文件能播；两个账号下同一集同档服务端只转一次。
- **D3 离线模式**：网络判断 + 离线首页 / 海报墙 / 只读详情 / 占位。单测覆盖判定规则（慢但成功永不判不可达；
  超时类要 30 秒 + 三次探测；两次硬失败即不可达；通路断开立即；挂起期 -1005 不计）。端到端用故障注入代理
  （延迟 / 限速 / 丢包 / 黑洞 / 门户 HTML）：慢网连用 10 分钟不误切；黑洞冷启动 40 秒内进离线；门户页几秒
  进离线；恢复自动回在线并补传。

**不做**：没下载的内容不支持离线浏览（首页快照照旧）；不用系统 HLS 下载（配不了我们的播放内核、字幕与
片段带不进去）；不做 DRM 与远程擦除；TV 端不做离线。

## 2. 成员管理（features/members + core/session）

### 2.1 模型与原则

- **两级固定角色（超管 / 成员）+ 成员级能力开关**，不做通用 RBAC。家庭场景资源公共（同一块盘、同一批
  种子），成员维度只隔离「个人体验数据」（进度 / 收藏 / 偏好 / 订阅归属），不隔离资源本身。
- **默认拒绝**：成员能做什么靠白名单声明；新增接口不声明就是管理员专属（服务端守护测试强制）。
- 超管不迁入成员表，继续留在服务器 \`auth.admin\` 配置域；登录同一个登录框，用户名区分。

**基线能力**（登录即有，无开关）：浏览可见库 / 条目 / 图片；播放 + 各自进度 / 已看 / 收藏；发现页；
个人设置（昵称 / 头像 / 密码 / 外观）。

**能力开关**（v1 全集，Flutter 设置页「成员」分区配置）：

| 开关 | 默认 | 控制功能 | Flutter 联动 |
|---|---|---|---|
| \`allow_subscribe\` | 开 | 发起/关注订阅、删除自己发起的订阅、search-now | 订阅入口按会话能力裁剪 |
| \`allow_search\` | 关 | 站点聚合搜索页与站点筛选器 | 搜索 Tab 对无权成员隐藏 |
| \`allow_direct_download\` | 关 | 搜索结果一键下载（成员版强制自动路由，无落盘路径） | 依赖 allow_search，UI 置灰、服务端独立校验 |
| 可见库 | 全部 | 白名单（\`all_libraries=false\` 时查关联表） | 不可见库对成员不存在（404 语义） |
| 可用站点 | 全部 | 白名单（仅 allow_search 开时生效） | 筛选 chips 只显示白名单站点 |

### 2.2 Flutter 会话层（core/session）

- \`SessionView\` 扩展：\`{ username, nickname, avatarUrl, role: admin | member, capabilities: { allowSubscribe,
  allowSearch, ... } }\`，由 \`GET /auth/me\` 返回；能力快照可空字段宽容解码（旧服务器缺字段 = 不支持对应功能，
  按钮不出现，与离线下载同口径）。
- \`AppShell\` 按 \`role\` 裁剪侧边栏与用户菜单：成员保留「新任务 / 媒体库 / 我的订阅」，设置页只剩「个人信息 /
  外观」，详情页隐藏删除/重识别/整理等管理操作。**前端裁剪只是体验，安全边界在后端 403**。
- 登录失败提示不区分「用户名不存在 / 密码错误」；限速分桶在服务端（按用户名），Flutter 不做本地限速逻辑。

### 2.3 成员管理页（features/settings/pages/members_page.dart，仅超管）

结构（列表 → 详情两层，编辑即保存，遵循 §3 设置页规范）：

1. **成员列表**：每行 = 头像 + 昵称（用户名）、状态徽标（启用/停用）、能力摘要（如「可订阅 · 可搜索
   (3 站) · 可见 2/5 库」）、最近登录时间。行尾「⋯」菜单：编辑 / 重置密码 / 停用（启用）/ 删除。
2. **新建成员**（列表头部主按钮，弹窗）：用户名 + 初始密码（默认一键生成随机密码并复制）+ 昵称（可选）。
   创建成功提示「把用户名和初始密码发给对方，登录后可自行修改」。不做邀请链接/邮件邀请（自部署无 SMTP 前提）。
3. **成员详情**：基本信息（昵称、头像只读、重置密码——生成新随机密码显示一次并复制）；能力开关三个
   （联动置灰，每个配一句中文说明）；可见库单选「全部库（含以后新建的）/ 仅选中的库」+ 库多选；
   可用站点同构（仅 allow_search 开时显示）。
4. **权限写入口唯一在成员页**（决策）：「库设置页配谁能见」的资源视角否决，避免两处写同一份关系；v1
   库页面零改动。

**生命周期语义**（UI 文案写明白）：

| 操作 | 会话 | 个人数据 | 其发起的订阅 |
|---|---|---|---|
| 停用 | 即时踢下线 | 全部保留 | 保持原样照常追更 |
| 启用 | 可重新登录 | —— | —— |
| 删除 | 同停用 | 服务端清理其进度、follower 行、偏好 | **转为超管发起**，绝不静默删订阅/下载；确认弹窗写明 |

### 2.4 成员侧订阅语义（features/subscriptions）

- 同一作品全局一份订阅（\`UNIQUE(media_item_id)\`）：成员 A 订阅 → 正常建订阅记发起人；成员 B 再订 → 幂等
  命中并写 follower 行，B 的「我的订阅」也看得到；B 取关只删自己的 follower 行；发起人取消且无其他
  follower → 真删，有 follower → 转移给最早的 follower。**成员的取消永远不影响别人正在追的内容**。
- 成员可见订阅列表 = 自己发起的 + 自己关注的；成员订阅一律用自动结论（规则组自动选组、目标库按收藏范围
  路由），没有「选库 / 选规则」的 UI；想追发起人没选的季提示「联系管理员或发起人调整」。
- 退出使用取关接口，不出现「删除订阅」（那是发起人 / 超管的动作）。

## 3. 设置页（features/settings）

### 3.1 页面结构规范（对齐 settings-ui.md）

- 一页由若干 \`SettingsSection\`（小节）组成：小节标题 + 可选说明；标题行右侧放整个小节的动作（添加 / 邀请）。
  内容列居中，表单类分区最大宽度约 640 逻辑像素；小节间距 40。
- **小节内容二选一**：

| 形态 | 组件 | 用于 | 保存方式 |
|---|---|---|---|
| 行组 | \`SettingsList\` + \`SettingsRow\` | 开关、下拉、单个文本值、只读信息、单个动作 | 即时生效，不配保存按钮 |
| 卡片 | \`SettingsCard\` | 多字段一起提交的表单（改密码、连接配置） | 页脚右侧唯一提交按钮，没填全置灰 |

- 行：左名称 + 一行灰色说明，右控件；行内错误贴在说明下方。
- 单个文本值（昵称）：输入框常驻，失焦或回车保存，Esc（Android 返回 / 失焦取消）放弃；成功轻提示，
  失败行内报错并回退。
- 卡片页脚：左限制条件或提示，右提交按钮；成功轻提示并清空一次性字段（密码）。

### 3.2 保存方式按控件类型

| 控件 | 保存 |
|---|---|
| 开关、单选、分段、下拉、芯片 | 改完即存（必要时 400 ms 合并连续改动），失败轻提示并重读服务端值 |
| 单个文本 / 数字 | 失焦或回车提交 |
| 多个相关字段（连接配置、模板、凭据） | 卡片或弹窗整体提交，页脚唯一提交按钮，未改动或不合法置灰 |

不再出现「整页底部一个保存按钮」管一堆开关的形态。

### 3.3 控件与按钮

- 开关用统一 \`McToggle\`（designsystem），不用原生复选框表示「立即生效的开关」。
- 分区内页签用 \`SettingsTabs\`（go_router query 参数驱动）；空列表统一 \`SettingsEmpty\`，文案提到的按钮必须
  真在屏幕上；警示/错误条统一 Banner 组件。
- 行尾「⋯」菜单统一 \`McMoreMenu\`：危险项标 danger（红字，自动排到分隔线后）；可逆但影响大的（停用）标

- **材质**：只复用 designsystem 的玻璃材质、按钮与线条令牌，主题换皮自动生效，组件内不写主题判断。

## 4. 影片分享（features/share + ShareBackend）

### 4.1 产品形态

超管在条目详情页「⋯」点「分享…」，得到一条链接；拿到链接的人不登录就能看这一部影片（剧集 = 整部，
含以后新入库的集），可设密码、可设有效期；一部影片同一时间只有一条有效链接，再点「分享」看到的就是它。

四条原则：①分享范围就是一个条目（不分季 / 集 / 文件）；②分享页是一张独立页（无侧栏、无导航、无站内入口）；
③访客不是成员（进度不落成员表、不进最近观看，活动页以「分享访客」出现，超管可随时结束播放 / 取消分享）；
④默认拒绝不破（分享接口是独立白名单通道，分享凭据到不了任何既有业务接口）。

### 4.2 创建方（详情页 ShareDialog）

- 「分享…」菜单项仅超管可见；点击先拉当前有效分享，按结果二选一：
  - **未分享**：对话框（海报 + 片名 + 说明「任何拿到链接的人都能观看这部影片，不需要登录」）。有效期档位
    1/3/7/30 天、默认 7 天，**无「永久」档**；密码默认关，打开时自动生成 6 位小写字母数字（去 0/o/1/l），
    可改可再生成（4–32 位）；剧集副标题写「剧集 · 已入库 3 季 24 集」提醒范围。生成成功后**同一对话框原地
    切到已分享形态**，不关闭不二跳。
  - **已有有效分享**：显示链接 + 密码（各带复制）、「7 天后失效（绝对时间）· 已打开 N 次 · 最近 …」、
    「复制链接和密码」（复制一段可直接发人的文本；无密码时叫「复制链接」）；「取消分享」二次确认
    「链接立即失效，正在播放的访客会在一分钟内中断」，确认后回未分享形态（可马上重新生成，slug 不复用）。
    过期 / 已取消的旧分享不出现。
- 链接地址 \`{external_url}/s/{slug}\`：\`external_url\` 未配置时后端回相对路径，前端用 \`Uri.base().origin\`
  补全并提示「在『设置 → 网络 → 外部访问』填写外网地址后，链接会用该地址生成」。

### 4.3 访客侧（Flutter 端分享入口）

Flutter App 的分享访客以**深链**进入：\`https://…/s/{slug}\`（App Links / Universal Links）或
\`movieclaw://share/<slug>\`。go_router 注册 \`/share/:slug\` 路由，进独立壳（无底栏、无侧栏）：

- **状态机**：探针 \`GET /api/v1/share/{slug}\` → 404 \`SHARE_NOT_FOUND\` →「分享不存在或已取消」整页；
  404 \`SHARE_EXPIRED\` →「分享已过期」；200 且 \`requires_password && !unlocked\` → 密码卡片（提交
  \`POST …/unlock\`；401「密码不对」；429「尝试次数过多，N 秒后再试」；成功后服务端 \`Set-Cookie\`）；
  否则进影片页。
- **密码之前不露任何信息**：不显示片名、海报。
- **影片页**：剧照背景 + 海报 + 标题/年份/评分/简介/演职员 + 版本 + 章节条 + ▶ 播放；剧集加季选择与分集
  横滚（缺片灰显）。顶部只有一条细栏：字标（不可点）+「链接 3 天后失效」。已登录成员打开分享链接看到的
  也是这张独立页（一种入口一种形态）。
- **播放走 ShareBackend**（\`core/player\`，见 01/03 文档）：接口基址换 \`/api/v1/share/{slug}/playback/…\`；
  档位判定与成员同规则（复用整条决策链）；取流用 \`?token=\`（token 负载 \`m=-1, sh=share_id\`，ttl =
  min(12h, 到期剩余)）；心跳 \`POST …/playback/progress\` 只刷新活动页实时会话，不写播放状态与日志；
  **续播记在本机**（secure storage 或 shared_preferences，键含 slug 与季集），换设备从头看；无已看标记、
  无播放次数；metrics / client-log 在分享作用域下不上报；退出目标固定回分享影片页。
- 取消分享后：转码档下一次 ping 404，播放器原地重开也 404，展示中文错误并停止；直连档下一个 Range 请求
  因分享行失效 404——两条路都在一分钟内。

### 4.4 管理与安全

- 媒体库管理页「分享」标签（超管）：列出全部有效分享（海报、片名、有效期、锁图标、打开次数、最近打开），
  行内「复制」「取消」；空态一句话。分享是对库内容的管理动作，与回收站同类，放管理页不放设置页。
- 条目删除级联删分享；条目仍在但无可播文件时分享页照常打开、播放按钮灰显提示「暂时没有可播放的文件」。
- 安全边界（服务端保证，Flutter 端配合）：slug 96 位随机、失败路径全 404；密码限流（5 次后指数退避）、
  密码之前不露片名海报；解锁 Cookie HttpOnly + Path 收窄到该分享；分享凭据访问站内接口 401；越出条目 404；
  取流 token ttl 不超过到期剩余；访客与成员同转码并发上限、活动页可结束、取消分享一键止损；分享 strm 条目
  语义为 302 到云端直链（对话框加提醒）；分享**刻意绕过库可见范围**（超管显式放出的条目）。
- P1 不做：分享编辑（改期 / 改密码，取消再建）、访客进度同步 / 已看标记 / 播放次数、单季 / 集 / 文件分享、
  「仅直连」开关、访客专属并发配置、成员分享。

## 5. 应用内更新（features/settings/pages/app_update_page.dart）

> 应用内更新是**服务器（Docker 部署）**的功能，Flutter App 不自更新；App 端的职责是「检查客户端自身新版 +
> 展示 / 触发服务器更新」。

### 5.1 服务器更新（超管，设置 → 应用）

- 后端提供检查 / 执行 / 回退 / 状态接口；Flutter 页面展示：当前运行版本、生效来源（镜像基线 / overlay vX）、
  镜像运行时版本、「检查更新」「立即更新」「回退」、下载进度条、changelog。
- **运行时版本契约**：\`manifest.json\` 声明 \`requires_runtime\`；不匹配时 UI 展示「本次更新包含运行时依赖变化，
  请升级 Docker 镜像」，禁用下载按钮——App 端只做展示，判定在后端。
- 更新执行（后端）下载 → sha256 校验 → 解包 → 备份 SQLite → 原子切换 → exit 43 全量重启；任何一步失败
  不影响运行中的版本。下载进度经现有事件通道（SSE）推送，Flutter 订阅同一事件流画进度条。
- **多版本回退**：版本选择器列出本地保留版本（默认 5 个，可调 2~20）与各自的 changelog；每档标数据兼容
  三态——\`switch\`（直接切）、\`restore\`（自动恢复对时备份，**UI 明示备份时间与数据损失范围**，用户知情确认）、
  \`unknown\`（强警告后可执行）。回退执行后容器全量重启，Flutter 重新走连接流程。

### 5.2 客户端自身更新（download-manifest 衔接）

- App「设置 → 关于」检查本端最新版：按本端产品（android / ios 侧载提示 / 桌面）查各自 GitHub Release 的
  \`downloads.json\` / \`release.json\`（schema 见原 download-manifest.md）；比较版本号提示新版，Android 直接给
  APK 下载入口（校验 sha256），iOS 侧载版给官网下载页链接。各端版本独立，不读服务器 Release。

### 5.3 自动检查

- 对齐服务端行为：定时（每小时 ETag 条件请求）+ 启动后延迟数分钟首查；发现新版经「待处理事项」提醒，
  **绝不自动安装**（更新会重启服务，必须用户主动触发）；用户 dismiss 的是具体版本，更新版本发布重新点亮；
  网络不可达静默跳过。

### 5.4 自愈事件外显

- 服务端入口脚本的自愈（坏版本回落基线、启动超时等）写入 \`updates/state/last-exit.json\`，后端启动后在
  「关于与更新」外显近 7 天记录；Flutter 页原样展示，让自愈不再悄无声息。

## 6. 通知中心与推送（core/notify）与使用提示（features/tips）

### 6.1 通知中心

- 轮询通知中心（30 秒）+ \`flutter_local_notifications\` 本地通知，见 01 文档 §3.1；本节补推送密文格式。

### 6.2 推送密文（push-payload）

推送端到端加密：实例加密，只有登录过该实例的设备能解密；中继和云端只看到密文。

**密钥**：App 为每个登录设备（实例 + 账号）生成 256 位随机密钥与随机 \`key_id\`（8 字节随机 base64url，
11 字符）；连同设备令牌、Bundle ID、环境、平台、支持的推送类型上报给实例（存 \`login_device\`，密钥加密存储，
退出登录随行删除）。Flutter 端密钥放 secure storage（iOS Keychain AfterFirstUnlockThisDeviceOnly 语义 /
Android EncryptedSharedPreferences），锁屏时通知扩展可读（iOS Notification Service Extension 经 App Group
共享钥匙串；Flutter 主工程需配置 App Group 与原生扩展）。App 每次启动、每次登录重新上报令牌和密钥。
退出登录删除本机密钥：之后该实例推送解不开，只显示通用文案。

**格式**：\`v1.<key_id>.<nonce>.<密文>\`；AES-256-GCM，nonce 12 字节随机（同密钥下绝不重复），
AAD = ASCII \`v1.<key_id>\`（防挪用）；nonce 与密文均 base64url 无填充。整串只含 base64url 字符与点，
满足中继对 \`payload\` 的检查。\`liveactivity\` 的 \`content-state\` / \`attributes\` 写成 \`{"e": "<同样格式的密文>"}\`。

**明文**（UTF-8 JSON，公共字段 \`v\`=1、\`type\`（与推送 type 一致防挪用）、\`sent_at\`、\`server{id,name}\`、
\`account{id,name}\`）：

- \`alert\`：\`title\` / \`body\` / 可选 \`subtitle\` / \`image\`（带签名的实例相对路径，不需登录凭证）/\`open\`
  （站内路径，网页与 App 同一路由）/\`thread\`（分组；App 再按服务器分开）/\`category\`（通知类别）/\`sound\`
  / \`actions\`（长按快捷操作：\`play\` / \`open\` / \`mute\`）/ \`grid\`（长按集数格子 \`{"season":1,"cells":"sssddww-m"}\`，
  s 看过 d 已入库 w 下载中 m 没找到 - 其他）/ \`source\`（要不要标来源：缺省不标；\`server\`=多服务器时标；
  \`account\`=同服务器多账号时标）。
- \`background\`：\`refresh\`（要刷新的数据，如 \`["continue_watching","badge"]\`）。
- 大小：最终推送 JSON ≤ 4096 字节；实例按 2200 字节控制 \`alert\` 明文，超时先截短 \`body\`。

**collapse_id**（对中继与苹果可见，必须不透明）：\`base64url(HMAC-SHA256(collapse_key, "<对象类型>:<对象ID>"))\`
前 16 字符；\`collapse_key\` 是实例本地 32 字节随机密钥，不发给任何人。

**解密与展示行为**（原生通知扩展，Flutter 不参与锁屏解密）：

1. 从 \`userInfo["e"]\`（或 \`payload\`）取密文，按 \`key_id\` 找密钥；解密校验 \`type\`；失败保留中继填的通用文案。
2. 设置标题 / 副标题 / 正文 / 分组 / 类别 / 声音；按 \`source\` 决定副标题标服务器或账号（内容类不标——点开时
   App 自动切到对应服务器和账号）。
3. \`image\`：从「实例地址 + image」下载配图，超时 5 秒，失败不带图；地址自带签名，扩展不需登录令牌；
   不用 TMDB 图床（国内连不上 + 暴露 IP）；纯局域网实例在外网收到的通知不带图。
4. 点开按 \`open\` 跳转，必要时先切换服务器与账号（go_router 深链 + session 选中逻辑）。
5. 遇到更高 \`v\` 尽力显示 \`title\`/\`body\`；拿到通知过滤权限后解不开的通知直接丢弃。

**测试向量**：实现必须用原 push-payload.md §7 的向量做单元测试——加密结果逐字节一致、解密还原明文
（Flutter 端用 \`cryptography\` / \`pointycastle\` 的 AES-GCM 实现；\`key_id=k7Qm2xP9Hn4\`、
\`nonce=000102030405060708090a0b\`、\`collapse_id=QuH-0hNhmLQa5h0c\`（输入 \`subscription:42\`））。

### 6.3 使用提示（features/tips，对标 TipKit）

**分工**：提示的文案、动作按钮、出现条件（规则）、出现在哪写在客户端（规则要读界面状态，新提示随发版即可）；
每人的状态（事件计数、每条提示的展示次数与作废记录）在服务端（多端共享，手机关过的提示电视上不再出现）。

**服务端接口**（成员区，命令行不可见）：

| 接口 | 作用 |
|---|---|
| \`GET /tips/state\` | 全量状态（\`events[]\` + \`tips[]\`），启动后第一次用到提示时拉一次 |
| \`POST /tips/events/{event_id}\` | 记一次用户行为，计数 +1 |
| \`POST /tips/{tip_id}/displays\` | 提示上屏一次，展示次数 +1 |
| \`POST /tips/{tip_id}/invalidate\` | 作废，body \`{"reason": "..."}\`（默认 \`action_performed\`）；以第一次为准 |
| \`DELETE /tips/state\` | 重置自己的全部状态 |

标识 \`^[a-z0-9][a-z0-9._-]{0,63}$\`，按「页面或功能.提示」命名；作废原因不是枚举，新端上报新原因旧服务端
照收；写入是原子 upsert（多设备同时上报计数不丢）。

**判定规则**（各端实现必须一致，引擎写成纯函数 \`tips_engine.dart\`，单测覆盖）：

1. 已作废 → 永不出现；
2. 设了 \`maxDisplayCount\` 且展示次数已到 → 永不出现（只在本地算，不写回服务端）；
3. 有一条规则不满足 → 暂不出现，条件满足立刻出现；
4. 没展示过的新提示受全局频率节流：上一条新提示第一次出现后 \`displayFrequency\` 内不出新的；
   \`ignoresDisplayFrequency\` 可豁免（当前服务端配置 0 即不节流）。

展示约定：**同屏只出一条**（有提示在屏时其他满足条件的排队，前一条关闭或离开页面后下一条接着出现）；
**上屏即锁定**（每次上屏记一次展示；已在屏上的提示不因这次展示把次数加到上限而当场消失，只有作废或
离开页面才消失）。快照拉回来之前不出任何提示（免得已作废的先闪一下）；上报一律先改本地再以服务端返回
为准；网络失败静默处理（提示不是关键功能）。

**Flutter 落地**：

- \`features/tips/\`：\`tips_engine.dart\`（纯函数判定内核）、\`tips_store.dart\`（状态 + 上报，Riverpod Notifier）、
  \`tip_card.dart\`（TipKit 式内联卡片：文案 + 动作按钮 + 关闭；动作回调执行后按 \`action_performed\` 作废，
  关闭按 \`closed\` 作废）、\`use_tip.dart\`（\`useTip(tip, params)\` → \`{visible, invalidate}\`，自定义样式用）。
- 用法对齐 Web 版：\`defineTip<T>({id, title, message, actions, rules, maxDisplayCount})\`；事件在用户行为
  处理函数里上报（不在 build / initState 里调，避免重复计数）；用户自己摸到功能时提示没出现过也可作废。
- **服务端代记事件**：有些事件不是看提示的人自己做的（如「家里有人在刷片」但只有管理员能开片段预切），
  服务端在业务链路上判定并写进要看提示的人的状态；客户端规则照常按事件计数判定。需要同时推送时以计数
  第一次变成 1 为准全服务器只推一次。服务端知道「功能已用上」时直接作废提示，不管在哪端操作。
- 已上线的提示沿用：\`library.reels-floor\`（下拉开始欣赏片段；旁白 / 读屏、离线时不出）；\`playback.reel-clips\`
  （开启片段预切，只给管理员，动作「去开启」）。
- 后续：气泡式提示（指向按钮）、设置页「重新显示使用提示」入口等第一批真实提示上线时再做；事件只存累计
  次数与首末时间，「最近 7 天做过 3 次」类规则需要时再加近期时间戳。
